# Kaspa x402 Batch Settlement Binding v1

Status: draft

This document defines a proposed Kaspa network binding for x402 v2 `batch-settlement`.

## Identifier

```json
{
  "scheme": "batch-settlement",
  "network": "kaspa:<network>",
  "extra": {
    "binding": "kaspa-escrow-v1"
  }
}
```

Initial network identifiers:

```text
kaspa:mainnet
kaspa:testnet-10
kaspa:testnet-12
```

Open item: confirm the final CAIP-style namespace or x402 registry entry for Kaspa networks.

## Asset and Amounts

`asset` is initially `"KAS"`.

All protocol amounts are decimal strings in atomic sompi units.

Display layers may show KAS or tKAS, but wire fields must not use floating point values.

## Payment Requirements

```json
{
  "scheme": "batch-settlement",
  "network": "kaspa:testnet-10",
  "amount": "1000000",
  "asset": "KAS",
  "payTo": "kaspatest:...",
  "maxTimeoutSeconds": 60,
  "extra": {
    "binding": "kaspa-escrow-v1",
    "templateId": "kaspa-x402-escrow-v1",
    "serverPublicKey": "<32-byte x-only hex>",
    "minDepositSompi": "90000000",
    "refundTimeoutDaa": "123456789"
  }
}
```

`amount` is the maximum per-request charge. A server may charge less and report the actual charge in `SettlementResponse.extra.chargedAmountSompi`.

`payTo` is the server payout address. It is not the client-specific escrow address.

## Payment Payload

The x402 v2 `PaymentPayload.payload` object is Kaspa-specific and uses a type discriminator.

Supported initial types:

- `deposit-voucher`
- `voucher`
- `refund`
- `claim`

Example voucher payload:

```json
{
  "type": "voucher",
  "channelId": "<canonical channel id>",
  "clientPublicKey": "<32-byte x-only hex>",
  "fundingOutpoint": {
    "txid": "<active escrow txid>",
    "index": 0
  },
  "voucher": {
    "amountSompi": "2000000",
    "signature": "<64-byte Schnorr signature hex>"
  }
}
```

## Voucher Digest

The voucher signs:

```text
sha256(
  sha256("kaspa:x402:escrow-voucher:v1") ||
  sha256(network) ||
  sha256(serialized active input scriptPublicKey) ||
  outpointTxid32 ||
  outpointIndex_le32 ||
  voucherAmountSompi_le64
)
```

The digest must bind to the exact escrow outpoint. A voucher for one escrow UTXO must not verify for a continuation or change UTXO.

## Toccata Requirements

The mainnet profile targets transaction v1 and Toccata covenants:

- v1 inputs use `compute_budget`.
- transaction builders must estimate script units.
- scripts must validate successor outputs.
- covenant IDs should be used for production indexability once wallet and builder support is ready.
- Silverscript source plus generated byte fixtures should be the reviewable covenant source of truth.

## Security Requirements

Implementations must reject:

- unsupported x402 version;
- unsupported scheme/network/binding;
- network mismatch;
- invalid public keys;
- invalid funding outpoint;
- deposit below `minDepositSompi`;
- voucher signed for the wrong network;
- voucher signed for the wrong script public key;
- voucher signed for the wrong txid or output index;
- voucher amount below required cumulative charge;
- claim amount above voucher amount;
- refund before `refundTimeoutDaa`;
- idempotency key reuse with a different request fingerprint.
